# 계정

Accounts 화면에서 대시보드의 계정 확인·추가·관리.
푸터 ⋯ 메뉴의 **Accounts**, 대시보드에서 **Return**, 메뉴 막대 아이콘 우클릭 후 **Accounts** 중 하나로 열기.
대시보드 행·프로바이더 헤더 우클릭 메뉴의 **Accounts**도 해당 계정 상세 열기.
왼쪽 위 뒤로 가기 버튼, Return, Esc로 한 단계씩 뒤로(계정 상세 → 목록 → 대시보드).

Accounts에서는 [Privacy Mode](/docs/settings.md#개인정보)와 관계없이 원래 이름·이메일 확인과 이름 편집 가능.
목록·상세와 이 화면에서 여는 전환·삭제 확인창의 계정 정보는 가리지 않음.

## 목록

- 대시보드 계정 줄 단위 1행: 손잡이 · 아이콘 · 프로바이더 이름 · 계정명.
- 켜진 프로바이더의 계정을 모두 표시하며, 지표를 모두 숨긴 계정도 포함.
- 저장 로그인이 없어 대시보드에서 빠진 Claude·Codex 등록 계정도 표시.
  계정명·저장 순서를 유지하며 상세에서 재로그인·제거 가능.
- 기본 CLI용으로 선택한 Claude·Codex 계정에 **In Use** 배지와 파란색 계정명 표시.
- 행을 누르면 계정 상세.
- 순서 변경은 [계정 순서](/docs/accounts.md#계정-순서) 참조.

## 계정 추가

1. 푸터의 **Add New Account** 클릭.
2. 프로바이더 선택.
   이미 켠 단일 계정 프로바이더는 **Added**로 표시하며 선택 불가.
   Claude·Codex는 계정을 여럿 둘 수 있어 항상 선택 가능.
3. 프로바이더 종류에 맞는 단계 진행.

| 종류 | 프로바이더 | 진행 |
|---|---|---|
| 공식 로그인 | Claude, Codex | **Add Account** 클릭.<br>첫 계정이고 이 Mac에 이미 로그인돼 있으면 다시 로그인 없이 가져옴.<br>그 밖에는 공식 로그인이 브라우저에서 열림.<br>실패하거나 취소하면 아무것도 등록하지 않으며 **Try Again**으로 재시도. |
| API 키 | OpenRouter, Z.ai | 키를 입력하고 **Add Account** 클릭.<br>**Get Your API Key** 링크로 키 발급 페이지 열기.<br>키는 이 Mac에 저장하며 환경 변수보다 우선, 저장 직후 사용량 조회.<br>이 Mac에 쓸 수 있는 키(환경 변수·저장 파일)가 이미 있으면 비워 둔 채 **Add Account**로 켜기만 가능. |
| 로컬 로그인 감지 | 그 밖의 프로바이더 | egasu가 이 Mac의 기존 로그인을 찾은 결과 표시 후 **Turn On**으로 켜기.<br>로그인을 찾지 못해도 켤 수 있으며, 조회 실패 시 대시보드에서 사유 표시. |

Claude·Codex 계정의 추가·전환·재로그인 동작은 [Claude와 Codex 계정](/docs/accounts.md#claude와-codex-계정) 참조.

## 계정 상세

- 상단 제목: Claude·Codex 등록 계정은 계정명, 그 밖은 프로바이더 이름.
  계정명을 누르면 그 자리에서 이름 변경 — Return 저장, Esc 취소.
  이름은 1~60자이며 `/`·`\` 사용 불가, 같은 프로바이더의 다른 계정과 중복 불가(대소문자 구분 없음).
  이름을 비우고 저장하면 별명을 지우고 그 계정의 로그인 이메일을 이름으로 사용.
  로그인 이메일을 아직 모르는 계정은 기존 이름을 유지하고 이름 입력 안내.
  이메일로 바뀐 이름은 이후 로그인이 바뀌어도 자동으로 바뀌지 않음.
  저장 실패 시 기존 이름을 유지하고 오류 알림 표시.
  패널을 닫으며 저장에 실패하면 다음 열기에 안내.
- 문제 카드: 사용량을 가져오지 못한 사유.
- **계정 설정** 카드: 계정별 지표의 손잡이 · 이름 · 핀 · 표시 스위치.
  한도 지표의 표시·순서는 이 계정에만 적용.
  메뉴 막대 고정은 같은 프로바이더 계정에서 공유하며 프로바이더당 최대 2개.
- **공통 설정** 카드: Claude·Codex의 Usage Trend·Today·Yesterday·Last 30 Days와 Codex Reset Watch.
  같은 프로바이더의 어느 계정 상세에서 바꿔도 표시·순서·메뉴 막대 고정을 공유.
  대시보드의 공통 이력 배치는 [계정 카드](/docs/dashboard.md#계정-카드) 참조.
- 지표 순서는 각 설정 카드 안에서 변경.
  순서를 바꿔도 기존 대시보드의 Always Visible·On Demand 소속은 유지.
  표시 스위치와 메뉴 막대 고정은 독립 — 숨긴 지표도 메뉴 막대에 고정 가능.
- Claude·Codex 등록 계정: 상태 배지, **Use This Account**, **Sign In Again…**, 중단된 전환 복구, **Remove Account…**.
  저장 로그인을 Keychain에서 읽지 못하면 **Sign In Again…** 대신 **Allow Keychain Access…** 표시 — macOS 승인 창을 띄워 다시 읽고, 성공하면 그 계정 사용량을 새로 조회.
  저장 로그인 자체가 없으면 **Sign-In Needed**와 **Sign In Again…** 표시.
  이 경우 **Use This Account**는 비활성, **Remove Account…**는 [계정 제거 조건](/docs/accounts.md#계정-제거) 적용.
- OpenRouter·Z.ai: API 키 상태(Not Set, From Your Environment, Saved in App, Custom Key)와 **Add API Key…**·**Replace API Key…**.
  저장한 키는 환경 변수보다 우선하며 저장 직후 새로 고침.
- 그 밖의 계정의 **Remove Account…**: 감지형 프로바이더는 추적만 끄고 로그인은 그대로.
  API 키형은 앱이 저장한 키만 지우고 끔 — 환경 변수 키는 그대로.
- 계정 제거 시 로컬 인증 파일·공유 홈(`~/.claude`, `~/.codex`)·다른 도구의 설정 유지.

새 설치·새 계정의 지표는 모두 켜짐으로 시작하며, 기존 공통 설정은 그대로 유지.
계정 전환 뒤에도 계정별 설정은 같은 프로필을 따라가며, 공통 설정은 프로바이더 단위로 유지.
두 설정 모두 앱 재실행 후 유지.
설정 이전 시 공통 지표는 공유 홈 계정 줄의 표시·순서·핀을 이어받으며, 추가 계정에 남은 공통 지표 설정은 사용하지 않음.
프로바이더 공용 레이아웃으로 저장된 계정별 지표는 알려진 계정마다 복사.
지표 표시 설정은 꺼진 지표만 저장.
기존 egasu 또는 OpenUsage의 켜진 지표 목록은 표시 상태를 유지한 채 꺼진 지표 목록으로 한 번 변환.
모든 지표를 숨긴 설정과 저장된 순서·고정도 유지.
이후 추가되는 지표는 기본 켜짐이며, 사용자가 꺼 둔 지표는 재실행·계정 전환 뒤에도 꺼짐 유지.

## Claude와 Codex 계정

Claude와 Codex는 계정을 여럿 등록하고 기본 인증 저장소를 쓰는 새 CLI 세션의 로그인을 전환 가능.
등록 계정은 사용자가 붙인 이름과 프로바이더 로그인 정보를 연결한 항목.
사용자가 선택하거나 편집할 폴더 경로 없음.
`~/.claude`와 `~/.codex`의 MCP 설정, 메모리, 플러그인, 스킬, 세션 기록 유지.
계정 전환은 기본 인증 저장소의 로그인만 교체.

`alpha`, `beta` 같은 계정명은 사용자가 관리하는 로컬 제목이며 이메일 주소나 영구 프로바이더 신원이 아님.
앱의 **Sign In Again…**에서 검증된 재로그인은 해당 계정명에 현재 저장된 프로바이더 신원과 인증 정보를 교체 가능.
두 계정명에 같은 프로바이더 신원의 인증 정보 저장 가능.
등록 계정은 프로바이더 신원과 별개로 관리하며, 이름 변경·재로그인·제거도 계정별로 수행.

### 로그인 추가

**Add New Account**에서 Claude 또는 Codex를 고른 뒤 **Add Account**로 추가.
이미 로그인된 상태이고 등록된 계정이 아직 없으면 현재 로그인을 바로 가져옴 — 새 브라우저 로그인 없음.
그 외에는 공식 Claude 또는 Codex 로그인 열림.
추가 계정은 egasu 소유의 비공개 작업 공간 안에서 로그인하므로, 로그인 중에도 현재 계정과 열려 있는 터미널은 계속 동작.
로그인 경로·인증 환경 설정은 앱이 실행한 로그인 자식 프로세스에만 적용.
두 번째 계정부터는 등록만 하고 기본 CLI 계정은 그대로 유지.
로그인을 취소하거나 실패하면 아무것도 등록되지 않음.
계정 목록을 읽지 못하는 동안에는 추가 불가.
첫 Claude 계정의 현재 로그인 검증이 실패하면 **Try Again**으로 다시 검증하거나 **Sign In Again**으로 공식 로그인 가능.
공식 재로그인은 해당 버튼을 명시적으로 선택한 경우에만 실행하며, 검증 전에는 계정 등록 없음.

### 로그인 상태

계정별 인증 정보는 macOS Keychain의 비공개 스냅샷으로 보관.

| 상태 | 의미 |
|---|---|
| Ready | 사용 가능한 저장 로그인이 있고 현재 앱 실행 중 사용량 확인 성공.<br>남아 있는 오류·경고 없음. |
| Session Expired | 토큰 갱신에서 세션 만료 확인. |
| Sign-In Needed | 만료된 액세스 토큰·폐기된 토큰·충돌한 토큰, 저장 로그인 부재·데이터 손상·신원 불일치. |
| Refresh Failed | 연결·서버·사용량 확인 문제 또는 Keychain 읽기 실패.<br>세션 만료로 취급하지 않음. |
| Checking | 저장 로그인 확인 중. |
| Not Checked | 로컬 확인 후 사용량 조회 전 또는 재로그인 직후. |

사용량 조회가 시스템 잠자기를 제외한 2분 안에 끝나지 않은 경우도 **Refresh Failed** 표시.
이전 조회가 종료된 뒤 재시도 가능.

이미 확인된 **Session Expired**·**Sign-In Needed**는 로컬 재확인 중이거나 Keychain 접근에 실패해도 유지하며, 재로그인으로 인증 정보가 바뀌면 해제.
재로그인하면 이전 인증 경고를 지우고, 새 확인 중에도 마지막 사용량 유지.

Keychain 잠금·접근 승인 대기로 저장 로그인을 읽지 못하면 **Refresh Failed**로 안내하며, 계정 전환을 통한 승인 재시도 허용.
자동 새로 고침은 승인 창을 띄우지 않음 — 계정 상세의 **Allow Keychain Access…** 또는 수동 새로 고침에서 승인.
해당 계정의 새로 고침이 끝나면 읽기에 실패했던 저장 로그인을 다시 확인 — 승인 후 계정 상세를 다시 열지 않아도 상태 갱신.

저장 로그인 확인은 화면 조작을 막지 않도록 백그라운드에서 실행하며, 화면 종료 또는 계정·선택·인증 변경 시 이전 결과 폐기.
계정 상세의 상태는 같은 계정의 대시보드 갱신 결과를 반영하며, 화면이 열린 동안에도 갱신.
마지막 사용량은 **Outdated**와 함께 남을 수 있지만, 해당 캐시를 읽는 것만으로 오류를 해제하거나 **Ready**로 판정하지 않음.
선택된 Claude 계정은 기본 CLI 로그인도 사용 가능하고 해당 계정명에 현재 저장된 신원과 일치해야 함.

### 계정 전환

계정 상세의 **Use This Account** 스위치로 기본 인증 저장소를 쓰는 새 CLI 세션의 계정 선택.
선택된 계정의 스위치를 끄는 동작은 무시 — 다른 계정의 스위치를 켜서 전환.
전환 후에도 같은 계정의 상세와 설정 유지.
계정 목록 갱신 후 같은 계정을 찾을 수 없으면 Accounts 목록으로 복귀.
전환은 확인 요청하며, 확인 버튼은 **Use {Provider}: {account_name}**으로 대상 프로바이더와 계정명 표시.
대시보드 계정 줄·지표 행의 우클릭 메뉴 **Use {Provider}: {account_name}**에서도 같은 전환 가능.
대시보드에서 전환하면 현재 화면 유지.
Privacy Mode를 켠 대시보드에서는 우클릭 메뉴와 전환 확인창의 계정명 대신 마스킹한 이메일 표시.
이메일이 없으면 **Account(계정)** 표시.

전환 전·후 계정의 인증 처리와 후속 사용량 갱신·사용 타이머 처리가 끝날 때까지 다음 계정 전환 차단.
다른 계정의 사용량 갱신·사용 타이머는 대기 대상에서 제외.
이미 시작된 외부 로그인 반영은 공유 계정 목록 갱신이 끝날 때까지 먼저 대기.
조회 오류가 표시되더라도 남은 작업이 종료된 뒤 다시 전환 가능.
전환 전에 시작한 새로 고침의 인증 반영 오류는 전환 후 계정에 표시하지 않음.
전환 중에는 계정 추가·재로그인·제거와 계정 사용량의 수동 새로 고침도 잠시 차단.
Accounts 화면 진입으로 시작되는 외부 로그인 반영도 전환 종료 전까지 생략.

승인하면 공유되는 Claude 또는 Codex 설정 홈 하나는 그대로 두고, 그 인증 정보만 선택 계정으로 교체.
교체 후 선택한 계정의 신원과 일치하는지 검증.
적용이나 검증에 실패하고 이전 인증 정보가 있으면 해당 정보로 복원 시도.
복원 자체가 실패할 수도 있으며, 이 경우 앱 로그에 복원 실패 기록.

### 중단된 Claude 전환 복구

Claude 전환은 인증 변경 전에 이 Mac에 복구 기록 저장.
사용자 계정 전환과 앱 시작·재로그인 전 복구에서는 전환 기록과 대조할 공유 인증 상태를 백그라운드에서 확인.
이 비동기 확인 중 앱에서 계정·선택·인증 정보를 변경하거나 복구 기록이 바뀌면 이전 결과 폐기.
전환 중 앱이 종료되면 다음 실행에서 외부 로그인 반영보다 먼저 해당 기록 확인.
공유 인증 정보와 계정 식별 정보가 전환 대상과 모두 일치하면 대상 계정의 선택 저장 완료.
공유 인증이 전환 전 상태와 같으면 이전 계정 선택 유지.
이 복구는 계정 선택만 정리하며, 기존 계정의 인증 스냅샷·로그인 작업 공간·프로바이더 신원은 교체하지 않음.

인증 정보가 일부만 바뀌었거나 새 외부 로그인과 섞여 전환 완료를 확인할 수 없으면 저장 계정을 보존하고 오류 기록·안내.
이 경우 오류에서 Accounts → Claude 계정 → **Use Claude: {account_name}** 재시도 경로 안내.
복구 기록 손상이나 인증 읽기 실패도 자동 로그인 반영을 중단하며, 선택 저장을 확인하기 전까지 복구 기록 유지.
선택 저장 실패는 별도 오류로 안내하며, 복구 기록 유지.

유효한 복구 기록이 남아 있으면 계정 상세 위쪽에 **Use Claude: {account_name}** 표시.
현재 선택된 계정도 이 버튼으로 전환을 다시 확인해 일부만 적용된 전환 재시도 가능.
이 재시도는 **Session Expired**나 **Sign-In Needed** 상태에서도 허용하며, 저장된 인증의 존재와 계정 신원 일치는 계속 검증.
저장 인증을 확인할 수 없으면 오류로 중단.
인증이 만료된 경우 전환 복구 후 **Sign In Again…**으로 재로그인 필요.

Claude 재로그인과 계정 제거는 남은 전환 기록을 먼저 복구한 뒤 진행.
재로그인 전에 전환 복구가 완료되면 계정 목록과 대시보드에 즉시 반영하며, 이후 재로그인을 취소해도 복구 결과 유지.

### 터미널 적용과 전환 조건

전환은 로그인 셸 종류로 제한하지 않음.
기본 인증 저장소를 쓰는 새 Claude·Codex 세션에 선택한 로그인 적용.
계정 전환 시 `~/.zshrc`·`~/.config/fish/config.fish` 등 셸 설정 파일은 수정하지 않음.
기존 `>>> OpenUsage` 함수 블록도 자동 제거하지 않음.
별도 인증 환경 변수·사용자 지정 인증 경로·API 키·Codex keyring을 쓰는 실행에는 선택 계정 적용을 보장하지 않음.
자세한 내용은 [CLI](/docs/cli.md) 문서 참조 — `egasu` 명령줄 도구는 필요 없음.

스위치는 로컬에서 사용 가능한 로그인 정보가 필요하며 **Session Expired**나 **Sign-In Needed**이면 비활성.
**Not Checked**, **Checking**, 일시적인 **Refresh Failed** 자체로는 전환을 막지 않음.
등록 계정이 남아 있는 한, 나중에 재로그인이 필요해져도 계정 하나는 선택 상태 유지.
인증 실패만으로 다른 계정을 자동 선택하지 않음.
이미 실행 중인 세션은 자동 재시작하지 않음.

### Claude 터미널 로그인 반영

기본 인증 저장소를 사용하는 Claude CLI의 `/login` 또는 `claude auth login`으로 로그인 가능.
egasu는 일반 Claude CLI의 기본 Keychain 인증을 우선하고, 해당 항목이 없거나 인증 형식이 잘못됐으면 `~/.claude/.credentials.json` 사용.
계정 정보는 `~/.claude.json`에서 확인.
현재 인증과 계정 정보를 확인할 수 있으면 변경된 토큰의 프로필 API로 계정·조직을 검증하고 내부 저장본에 반영.
별도 인증 경로나 환경 변수를 쓰는 로그인은 이 반영 경로의 대상이라고 보장하지 않음.

이미 등록된 다른 계정으로 외부 로그인하면 그 계정의 저장본을 갱신하고 선택 이동 — 이전 계정의 저장 로그인·이름·지표 설정 보존.
같은 신원의 등록 계정이 여럿이면 현재 선택 계정을 우선하며, 해당하지 않으면 먼저 등록된 계정 선택.
미등록 신원으로 외부 로그인하면 현재 선택 계정명에 신원과 인증 정보 반영.
UI가 아직 변경을 감지하지 못했으면 수동 새로 고침으로 현재 인증 재확인.

외부 로그인 반영은 CLI의 Keychain·인증 파일·계정 상태 파일을 다시 쓰거나 다른 위치의 로그인을 정리하지 않음.
확인 중 로그인이 바뀌거나 토큰의 계정·조직이 관찰한 상태와 다르면 저장본을 보존하고 다음 갱신에서 재확인.
프로필 조회·Keychain 저장 실패는 로그와 계정 오류로 표시하며 CLI 로그인 유지.
현재 로그인을 확인할 수 없거나 충돌 안내가 표시되면 Accounts → Claude 계정 → **Sign In Again…** 사용.

### 사용량 조회

등록 계정의 대시보드 배치는 [계정 카드](/docs/dashboard.md#계정-카드) 참조.
한도 지표의 표시·순서는 계정 단위이며, 메뉴 막대 고정은 프로바이더 단위.
로컬 사용 내역과 Codex Reset Watch는 프로바이더 공통 설정 사용.
미등록 공유 홈 로그인은 별도 계정 줄로 추가하지 않음.
비활성 계정의 사용량은 Keychain 인증 스냅샷의 토큰으로 프로바이더 API에서 조회.
스냅샷의 토큰이 만료되면 갱신된 토큰을 같은 스냅샷에 다시 저장.
Codex 갱신 도중 그 계정을 선택하면, 공유 인증 원문이 요청 시작 시 스냅샷 또는 이전 동기화 실패로 남은 원문과 같을 때만 공유 홈에도 갱신본 반영.
공유 홈 저장 실패 시 오류를 안내하고, 다음 전환에서도 갱신된 스냅샷을 이전 공유 토큰으로 덮어쓰지 않도록 보존.
저장 실패 뒤 공유 파일 읽기까지 실패하면 가능한 이전 인증들을 함께 기억해 최신 토큰 보존.

### 재로그인

**Sign In Again…**은 앱 안의 복구 경로로 제공하며, 현재 CLI 로그인을 확인할 수 없거나 Claude 로그인 충돌이 있을 때 사용 가능.

Codex 재로그인은 시도마다 빈 작업 공간에서 실행하며 기존 저장 인증을 로그인 명령에 전달하지 않음.
로그인 성공 후 해당 시도의 인증만 재로그인을 시작한 계정명에 반영하고, 성공·실패·취소 후 임시 작업 공간 정리.
시도별 작업 공간은 해당 계정의 작업 공간 아래에 생성하며, 앱 비정상 종료로 남은 파일도 계정 제거 시 함께 삭제.
로그인 작업 공간 경로에 심볼릭 링크가 있으면 인증 읽기를 중단하고 기존 저장 인증과 터미널 로그인 유지.
Codex 로그인 작업 공간의 인증은 일반 파일에서만 가져옴.
Codex 로그인 완료 시 다른 계정이 선택돼 있으면 새 인증은 재로그인을 시작한 계정명에만 저장하고 현재 터미널 로그인 유지.

**Sign In Again…**은 완전하고 검증 가능한 프로바이더 로그인이면 계정명에 저장된 인증 정보와 프로바이더 신원을 교체.
계정 상세는 이 복구 동작과 함께 현재 실패의 상세 원인 표시.
재로그인 완료 시 해당 계정의 이전 확인 결과를 해제하고, 프로바이더가 켜져 있으면 신원이 같아도 새 확인 요청.
확인 성공 시 **Ready** 복구 — 로그인 변경 전에 시작된 요청의 결과는 폐기.
프로바이더 신원이 바뀌거나 다른 계정명에도 같은 신원이 저장돼 있어도 계정명을 바꾸거나 다른 계정을 선택하지 않음.

### 계정 제거

제거는 그 계정의 egasu 로그인 작업 공간을 먼저, 다음으로 Keychain 스냅샷을 지우고, 마지막에 레코드 등록 해제.
Claude 로그인 작업 공간 정리 시 전용 Keychain 인증을 먼저 제거한 뒤 디렉터리 삭제.
`~/.claude`와 `~/.codex` 데이터는 절대 건드리지 않음.
둘 중 하나라도 삭제가 실패하면 다시 시도할 수 있도록 계정 등록 유지.
작업 공간 삭제가 실패한 경우에는 스냅샷도 전환 가능한 상태로 남김.
다른 계정이 있는 동안에는 선택된 계정 제거 불가 — 먼저 전환 필요.

계정 추가·이름 변경·재로그인·제거는 대시보드 계정 줄과 Accounts 목록을 즉시 갱신.
egasu 재실행 불필요.
저장된 계정 레지스트리를 디코딩하거나 검증할 수 없으면 egasu는 원본 데이터를 그대로 둠.
레지스트리를 빈 목록으로 바꾸는 대신 Accounts에 오류를 표시하고 계정 변경 차단.

## 계정 순서

Accounts 목록에서 행 왼쪽 손잡이를 드래그해 순서 변경.

- 같은 프로바이더 계정끼리는 계정 순서 변경.
- 다른 프로바이더 사이 이동은 양쪽 모두 계정이 1개일 때만 — 프로바이더 순서 변경.
- 대시보드에서는 카드 안 지표와 드래그 가능한 프로바이더 헤더의 순서 변경([순서 바꾸기](/docs/dashboard.md#순서-바꾸기) 참조).
- VoiceOver는 같은 프로바이더 계정이 여럿인 행에 **Move Up**과 **Move Down** 동작을 제공하고 이동 후 새 위치 안내.

계정 순서는 Accounts 목록, 대시보드, 공유 이미지에 즉시 적용.
바꾼 순서는 패널 닫기·앱 재실행 후에도 유지.

기본 순서는 계정 등록순이며 새 계정은 사용자 지정 순서의 마지막에 추가.
이름 변경, 재로그인, 새 터미널 세션 계정 전환과 재실행 후에도 순서 유지.
계정 제거 시 남은 계정의 상대 순서를 유지하며 같은 이름을 다시 등록하면 새 계정으로 마지막에 추가.
일시적으로 대시보드 줄이 없는 계정도 저장된 위치를 유지하고, 줄이 다시 생기면 해당 위치로 복귀.

프로바이더 순서와 계정 순서는 따로 저장 — 한쪽을 이동해도 다른 쪽 순서 유지.
⌘Z 실행 취소는 프로바이더 순서는 되돌리지만 계정 순서는 대상 아님.
계정 정렬은 계정 선택, 인증 정보, 지표 레이아웃과 사용량 데이터를 변경하지 않음.
계정 순서는 이 Mac에만 저장하며 iCloud 동기화에서 제외.
