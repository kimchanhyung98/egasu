# 명령줄 인터페이스

egasu는 에이전트와 스크립트용 1회 실행 명령 `egasu`를 제공.
기본 명령은 [`/v1/limits`](/docs/local-http-api.md#get-v1limits) JSON을 출력한 뒤 종료.
메뉴 막대 앱을 실행하거나 백그라운드 프로세스를 남기지 않음.
출력에는 한도와 잔액 포함.
UI 행, 색상, 부제목, 차트, 지출 내역 타일은 출력 대상에서 제외.
HTTP 라우트와 같은 스키마 사용.
CLI 출력의 `displayName`에는 Claude·Codex 계정명이 포함될 수 있으므로 연동 시 프로바이더 ID로 구분.

```sh
egasu                 # 활성화된 모든 프로바이더, 오래된 캐시 항목만 새로 고침
egasu codex           # 프로바이더 하나, 캐시가 오래됐을 때만 새로 고침
egasu codex --force   # 공유 프로바이더 엔진으로 새로 고침 후 캐시·출력·종료
```

CLI와 앱은 프로바이더 조회·인증·가격 계산·캐시 처리를 공유.
일반 조회는 일반 사용량 5분·Claude 15분 이내의 스냅샷을 재사용하고, 없거나 오래된 것만 새로 고침.
OpenCode는 현재 터미널의 Go 키 또는 `auth.json`으로 조회하며 이전 실행의 계정 한도 캐시는 재사용하지 않음.
Claude 계정 신원을 확인할 수 없으면 유효 기간 안의 캐시도 재사용하지 않고 새 조회의 확인 실패를 표시.
`--force`는 캐시 유효 기간과 관계없이 새 조회를 요청하고 성공한 결과를 같은 캐시에 기록.
Claude의 계정별 429 대기 상태는 앱과 공유하며 `--force`로도 우회 불가.
앱과 CLI가 같은 Claude 계정·조직의 같은 사용량 API를 동시에 조회하면 파일 잠금으로 요청을 조정하고 완료 결과 공유.
CLI 조회는 구독 타이머용 메시지를 전송하지 않음.
CLI는 Mac에 저장된 인증 정보로 해당 프로바이더 API를 조회.
토큰과 API 키는 출력 JSON에서 제외.

프로바이더 인자는 [로컬 HTTP API](/docs/local-http-api.md)와 같은 문자열 일치 방식으로 해석.
정확한 프로바이더 ID는 해당 카드 하나를 지정.
패밀리 ID(`claude`, `codex`)는 CLI에서 조회 가능한 해당 프로바이더의 계정 카드 전체를 지정.
비활성 관리형 계정의 인증 스냅샷을 사용하는 카드는 CLI 조회 대상에서 제외.
CLI는 앱이 만든 계정 인증용 Keychain 항목의 존재 여부만 확인하며, 저장된 인증 스냅샷으로 사용량을 조회하지 않음.
앱의 로컬 API에서는 비활성 관리형 계정 카드도 조회 가능.
출력 객체에는 일치한 모든 프로바이더가 담기고, 아무것도 가리키지 않는 ID는 오류로 종료.
별칭이나 계정 선택 로직은 없음.

앱의 Language 선택과 관계없이 CLI의 JSON 필드·지표 ID·단위·오류 원문은 기존 계약 유지.
사용자 계정명은 입력한 원문으로 출력.

OpenCode Go의 주간·월간 Soft Limit 사전 검사는 해당 계정의 서버 응답을 사용.
로컬 지출 추정치만 있으면 판정은 `unknown`.

## 소프트 한도 확인

`egasu soft-limit check <card-id>`는 새 작업을 시작하기 전에 지정한 카드 하나의 [소프트 한도](/docs/settings.md#소프트-한도)를 확인.
앱에 저장한 기간과 기준값을 사용하며, 결과는 JSON으로 출력하고 종료 코드로 전달.

**설정 → 실험실 → 소프트 한도 → 터미널 명령 → 명령 복사**에서 원하는 동작과 프로바이더를 선택.
**CLI 시작**은 Codex·Claude·Kimi의 한도를 확인한 뒤 허용된 경우에만 기본 CLI를 시작.
프로바이더의 CLI가 설치된 터미널에서 복사한 명령을 실행.
복사한 시작 명령은 `PATH`에서 프로바이더 실행 파일을 찾으며 같은 이름의 셸 별칭과 함수는 건너뜀.
egasu에서 사용량을 확인하는 계정과 같은 계정으로 로그인한 터미널에서 실행.
**한도 확인**은 시작 없이 상태를 조회.
복사한 명령은 현재 앱에 포함된 도우미를 사용하므로 전역 터미널 도우미 설치 없이도 실행 가능.
Claude·Codex에서 비활성 계정의 저장본은 명령의 확인 대상에서 제외.

```sh
egasu soft-limit check codex && /usr/bin/env codex -c 'cli_auth_credentials_store="file"'
```

이 예시는 확인 명령이 성공한 경우에만 새 Codex CLI 실행.
이미 실행 중인 대화는 계속 진행.

| 종료 코드 | 결과 | 의미 |
|---|---|---|
| `0` | `disabled`, `belowLimit` | 소프트 한도가 꺼져 있거나 확인한 사용률이 기준 미만 |
| `3` | `reached` | 선택 기간의 한도 중 하나 이상이 기준에 도달 |
| `4` | `unknown` | 프로바이더 비활성, 지원 지표 없음, 조회 실패, 만료 또는 추정치로 판정 불가 |
| `2` | 명령 오류 | 잘못된 인자 또는 알 수 없는 카드 ID |

정확한 카드 ID를 지정하며 같은 프로바이더의 다른 계정으로 확장하지 않음.
결과가 `unknown`이면 [로컬 로그](/docs/logging.md)에서 `Soft Limit preflight`의 `reason` 확인.
예를 들어 `rate_limited`는 조회 대기, `identity_unverified`는 계정 미확인, `incomplete_quota`는 일부 한도로 판정할 수 없는 상태.
예를 들어 Codex 카드의 기준에 도달하면 표준 출력에 `{"cardId":"codex","status":"reached"}`를 반환하고 종료 코드 `3` 사용.
CLI 조회에 사용할 수 없는 비활성 계정의 저장된 인증은 읽지 않음.
Codex·Claude는 터미널의 로그인 경로나 인증 환경 변수가 앱의 한도 조회와 다른 인증을 사용하게 하면 한도 미확인 반환.
Codex 시작 명령은 한도 확인에 사용한 `auth.json`의 로그인을 사용하도록 해당 실행에만 파일 인증 저장소를 지정.
파일에 저장된 로그인이 필요. 기존 Codex 설정은 유지.
Keychain에만 로그인한 경우와 관리자 정책에서 인증 저장소를 강제하는 경우는 Codex 시작 명령의 지원 범위에서 제외.
소프트 한도를 끄면 이전에 복사한 시작 명령은 한도 검사 없이 실행. Codex 시작 명령에는 파일 인증 저장소를 계속 지정.
Claude의 터미널 검사는 Claude Desktop 계정 대신 CLI 로그인을 사용.
같은 Claude 폴더를 가리켜도 `CLAUDE_CONFIG_DIR` 설정값에 따라 별도 Keychain 항목 사용 가능.
Kimi는 터미널의 기본 모델이 Kimi Code 프로바이더에 연결되고 사용량 조회와 같은 인증을 쓰는지 확인.
기본 모델을 확인할 수 없거나 `KIMI_MODEL_NAME`으로 임시 모델을 지정하면 한도 미확인 반환.
선택한 모델이 다른 서비스로 요청을 보내거나, 사용자 지정 헤더가 인증을 바꾸거나 해석할 수 없으면 한도 미확인 반환.
조회 과정에서 토큰을 갱신하면 실제 한도 요청에 쓴 새 인증과 터미널 인증을 비교.
비교 결과가 다르거나 인증을 읽을 수 없으면 한도 미확인 반환.
Codex·Claude·Cursor는 현재 로그인과 일치하고 출처를 확인할 수 있는 유효한 실측 캐시를 사용.
표시용 캐시의 실측값이 없거나 불완전해 판정할 수 없으면 사용량을 다시 조회.
캐시를 어느 계정에서 얻었는지 확인할 수 없는 프로바이더는 지정한 카드만 새로 조회.
사전 검사에서 얻은 새 한도와 실패에 따른 무효화는 해당 실행의 메모리에 보관.
선택한 기간에 추정치만 제공하는 카드는 새로 조회하지 않고 한도 미확인 반환.
Claude 조회 대기 중에는 대기 규칙을 따르며 `--force`는 미지원.

## `PATH`에 설치

1. **설정 → 일반 → 업데이트**에서 **베타 업데이트** 켜기.
2. **실험실 → 명령줄**(Labs → Command Line) 열기.
3. **터미널 도우미 → 설치…**(Terminal Helper → Install…) 선택.
4. macOS 관리자 승인 요청 완료.
5. 앱이 설치를 확인해 버튼이 **제거**(Uninstall)로 바뀌면 터미널에서 `egasu` 실행.

설치 과정에서 `/usr/local/bin/egasu`가 이 앱의 `Contents/Helpers/egasu`를 가리키고 실행 가능한지 확인.
같은 경로에 다른 파일이 있으면 해당 파일을 보존하고 **사용 불가**(Unavailable) 표시.
베타 업데이트를 꺼도 설치된 명령은 계속 사용 가능.
제거하려면 베타 업데이트를 켠 상태에서 **실험실 → 명령줄 → 제거** 선택.
앱의 확인창에서 제거를 선택하고 macOS 관리자 승인을 마치면 이 앱의 링크만 제거.
확인창이나 관리자 승인 요청을 취소하면 기존 링크 유지.

설치된 심볼릭 링크는 egasu 안의 서명된 헬퍼를 가리키므로, 앱을 제자리 업데이트하면 명령도 함께 갱신.
번들 내부에는 이전 `openusage` 헬퍼 이름도 유지하므로 기존 설치 경로를 유지하는 업데이트에서는 이전 명령도 계속 동작.
OpenUsage에서 자동 업데이트한 첫 실행은 이 앱을 가리키는 기존 명령 링크도 새 앱 경로로 변경.
링크 폴더에 쓰기 권한이 없으면 macOS 관리자 승인 요청.
승인을 취소하거나 변경에 실패하면 기존 앱과 명령 링크 유지.
복원 작업도 실패한 경우에는 오류 안내에 따라 `egasu.app`을 다시 열어 명령 링크 복구 재시도.
이름 변경 직후 앱이 중단돼도 같은 방식으로 기존 명령 링크 복구.
사용자가 앱을 다른 폴더로 옮겼다면 기존 `egasu` 링크를 제거한 뒤 새 앱에서 다시 설치.
개발용 기본 설정 도메인은 비어 있지 않은 `EGASU_DEFAULTS_SUITE`를 우선 사용하며, 없거나 빈 값이면 이전 `OPENUSAGE_DEFAULTS_SUITE` 사용.
CLI의 설정 도메인과 앱 소유 파일 저장 경로는 같은 앱 식별자로 결정.
운영 식별자 `com.kimchanhyung98.openusage`의 저장소 이름은 `egasu`.
표준 개발 식별자 `com.kimchanhyung98.openusage.dev`의 저장소 이름은 `egasu.dev`.
개발 앱의 헬퍼와 이를 가리키는 심볼릭 링크도 같은 저장소 이름 사용.
나머지 설정 도메인은 전체 식별자의 SHA-256으로 만든 고정 저장소 이름 `egasu.suite.<해시>` 사용.
앱 소유 파일은 `~/.config/<저장소 이름>/`·`~/Library/Application Support/<저장소 이름>/` 폴더로 분리.
관리형 계정 인증 스냅샷도 같은 이름을 Keychain 접두어로 사용해 분리.
공식 Claude·Codex·Antigravity 도구와 공유하는 Keychain 항목은 기존 이름 유지.

업데이트 뒤 앱보다 CLI 조회를 먼저 실행해도 `~/.config/openusage`의 OpenRouter·Z.ai 키 파일을 해당 저장 경로로 복사.
원본과 이미 존재하는 대상 파일은 유지.
키 파일 이전이 완료된 뒤 사용자가 삭제한 키는 이전 원본에서 다시 복원하지 않음.
새 설치에서 CLI가 사용량과 관찰된 계정을 캐시해도 앱을 처음 열 때 로컬 프로바이더 탐지.
기존 앱 설정이 있는 설치는 저장된 활성 프로바이더 유지.
Claude의 429 대기·마지막 정상 사용량도 조회 전에 이전하여 기존 대기 시간 유지.
운영 빌드는 상태 파일을 이동하고 개발 빌드는 원본을 복사.
이미 존재하는 계정 상태 파일은 유지하며, 아직 없는 다른 계정의 파일만 추가.
이전 대상 계정의 기존 조회가 진행 중이면 오류로 종료하고 조회 완료 후 재시도.
기존 잠금 파일은 원래 위치에 유지.
계정 Keychain과 나머지 앱 전용 상태의 이전은 앱 첫 실행에서 별도로 수행.
이전 실패 시 오류를 기록하고 조회 실패로 종료.

기본 사용량 조회의 종료 코드는 성공 `0`, 잘못된 인자나 알 수 없는 프로바이더 `2`, 새로 고침이나 로컬 읽기 실패 `4`.

## 계정

계정 관리는 앱의 [**Accounts**](/docs/accounts.md)에 있음.
CLI는 동일한 등록 계정과 선택된 터미널 계정을 조회:

```sh
egasu account list [claude|codex] [--json]   # 등록된 계정; *는 선택된 계정 표시
egasu account current [claude|codex]         # 선택된 계정의 이름(스크립트용)
```

도구를 생략한 `current`는 두 도구를 모두 출력.
도구를 지정하면 계정 이름만 출력하고, 선택된 계정이 없으면 아무것도 출력하지 않음.
종료 코드는 성공 `0`, 사용법 오류 `2`, 저장된 계정 레지스트리를 읽거나 검증할 수 없을 때 `4`.
이때 CLI는 빈 계정 목록 대신 오류를 출력.
계정 목록은 Accounts에 저장한 사용자 지정 표시 순서가 아니라 레지스트리 순서 유지.

계정에는 사용자에게 보이는 폴더도, 실행 명령도 없음.
전환은 공유 설정 홈의 인증 정보 교체.
`egasu` 명령 설치 여부와 무관하게 기본 인증 저장소를 쓰는 새 `claude`·`codex` 세션에 선택한 로그인 적용.

Accounts에서 계정을 전환하면 먼저 확인을 요청.
승인하면 Claude CLI가 사용하는 위치의 인증과 계정 정보만 교체.
Codex는 `~/.codex/auth.json` 교체.
MCP 설정·메모리·세션 등 다른 공유 홈 데이터 유지.
전환은 로그인 셸 종류로 제한하지 않음.
계정 전환은 셸 설정 파일과 터미널 환경 유지.
이전 OpenUsage가 설치한 Claude 함수는 egasu 앱이 로그인을 기본 위치에서 확인한 뒤 자동 제거.
이전 결과와 보류 조건은 [이전 Claude 셸 함수 정리](/docs/accounts.md#이전-claude-셸-함수-정리) 참조.
이전 Codex 함수를 제거하려면 설치에 사용한 셸 설정 파일에서 두 마커의 프로바이더 이름이 모두 `codex`인 블록 전체 삭제.
삭제 후 새 터미널 창 열기.

터미널의 인증 환경 변수나 사용자 지정 인증 경로는 변경하지 않음.
`CLAUDE_CONFIG_DIR`·`CODEX_HOME`, 별도 API 키·인증 환경 변수·Codex keyring을 쓰는 실행은 CLI 설정에 따라 다른 인증을 선택할 수 있음.
해당 실행에 계정 전환이 우선 적용된다고 보장하지 않음.

앱의 첫 계정 공식 로그인은 기본 인증 저장소 사용.
이전 OpenUsage의 기본 Claude 함수를 사용하는 경우에만 Claude 로그인 자식 프로세스에도 공유 `~/.claude` 경로 지정.
추가 계정·재로그인은 해당 자식 프로세스에만 같은 변수를 로그인 작업 공간으로 설정.
해당 자식 프로세스에서 인증을 덮어쓰는 환경 변수를 제거하며, Codex 로그인은 파일 인증 저장소 사용.
터미널의 환경 변수와 Codex 인증 저장소 설정은 그대로 유지.

### Claude 터미널 로그인 반영

기본 인증 저장소를 사용하는 `claude` 세션의 `/login` 또는 `claude auth login`으로 로그인 가능.
egasu는 사용량 조회·전환에 사용하는 인증과 같은 위치에서 터미널 로그인 감지.
일반 CLI와 이전 OpenUsage 셸 함수의 인증·계정 정보 위치는 [Claude 터미널 로그인 반영](/docs/accounts.md#claude-터미널-로그인-반영) 참조.
현재 인증과 계정 정보를 확인할 수 있으면 변경된 토큰의 계정·조직을 검증한 뒤 Keychain 스냅샷과 저장 신원에 반영.
계정 정보에 조직이 없으면 API로 확인한 전체 신원으로 등록 계정을 찾고 egasu 저장본에만 조직 보완.
별도 인증 경로나 환경 변수를 쓰는 로그인은 이 반영 경로의 대상이라고 보장하지 않음.
이미 등록된 신원이면 해당 계정의 저장본을 갱신하고 선택 이동.
같은 신원의 계정이 여럿이면 현재 선택 계정을 우선하며, 해당하지 않으면 먼저 등록된 계정 선택.
미등록 신원이면 현재 선택 계정명에 신원과 인증 정보 반영.
변경을 아직 감지하지 못한 경우 수동 새로 고침으로 현재 인증 재확인.
완료되지 않았거나 신원을 검증할 수 없는 로그인은 기존 스냅샷을 변경하지 않음.
이 확인에서 만료된 토큰을 자동 갱신하지 않으며, CLI에서 로그인을 갱신하거나 **Sign In Again**으로 재로그인한 뒤 재시도.
외부 로그인 반영은 기본·공유 CLI 인증 저장소의 Keychain·인증 파일·계정 상태 파일을 다시 쓰거나 다른 위치의 로그인을 정리하지 않음.
egasu의 계정별 Keychain 스냅샷, 앱 소유 로그인 작업 공간, 계정 등록·선택 상태 갱신.
현재 로그인을 확인할 수 없거나 충돌 안내가 표시되면 **Accounts → Claude 계정 → Sign In Again…** 사용.
