# Cursor

Cursor 앱 또는 CLI의 기존 로그인으로 Cursor 요금제 사용량 추적.

## 추적 항목

| 지표 | 의미 |
|---|---|
| Credits | 지급 크레딧과 선불 계정 잔액에서 남은 크레딧 |
| Total Usage | 청구 주기의 요금제 사용량(백분율 또는 달러, 요청 기반 Enterprise 계정에서는 포함 요청 한도 대비 사용한 요청 수) |
| Requests | 커스텀 레이아웃에서 선택적으로 따로 표시하는 포함 요청 한도 대비 사용한 요청 수 |
| Auto Usage | Auto 모델 사용 백분율 |
| API Usage | API 사용 백분율 |
| Extra Usage | 온디맨드 지출 — 가능하면 사용자 단위, 아니면 팀 집계이며 Cursor에서 한도를 반환하면 미터로 표시 |

Cursor가 요금제 이름을 보고하면 egasu의 프로바이더 이름 옆에 표시.
Cursor·Grok·X 통합 계정은 주간 공유 한도를 Total Usage 한 줄로 표시.
요금제 조회에 실패하면 같은 계정에서 확인한 통합 판정을 유지하고, 통합 여부를 확인하지 못했으면 Stripe 응답에서 확인.
Credits는 통합 계정의 선불 잔액, Extra Usage는 대시보드가 보고한 월간 추가 사용액.
사용량·이력 조회 도중 Cursor 로그인이 바뀌면 이전 계정의 사용량·잔액 제외.
추가 사용을 끄거나 상한이 0이면 해당 행을 숨김.
주간 사용량을 받지 못해도 상한이 있는 월간 추가 사용액은 독립적으로 회복 알림 판정.
개인 한도와 팀 공유 한도는 각각 같은 범위의 소진·회복을 비교.
지출액과 상한의 집계 범위가 다르거나 확인되지 않으면 해당 행의 회복 알림 생략.
요청 수가 Total Usage를 대체할 때는 Requests에서만 요청 한도 회복을 판정하고 구독 한도의 소진 기록은 유지.
추가 지출 상한이 없으면 사용액만 표시하며, 이 지출은 소프트 한도 판정에서 제외.
구독 한도만 있고 사용량·잔여량·사용률이 모두 없으면 해당 지표 생략.
사용량이나 사용률이 0으로 명시되면 그대로 표시.
소프트 한도는 확인된 청구 주기가 7일 또는 한 달(28~31일)인 Total Usage·Requests·Auto Usage·API Usage에 적용.
요청 기반 요금제는 Cursor가 제공한 월 시작일로 한 달 주기를 확인.
주간 총사용량과 월간 요청 한도가 함께 있으면 각 지표에 해당 기간을 적용.
주기를 확인할 수 없으면 사용량만 표시.
일부 구독 한도의 수치가 누락되면 확인된 지표는 계속 표시하고 해당 주기의 소프트 한도 미도달 판정은 보류.
신규 판매 요금제는 The X Subscription의 Free·Plus·Premium·Super·Ultra와 팀·기업 계약.
기존 Cursor 요금제 이름은 그대로 처리하며, [구독 가격과 전환 조건](/docs/pricing.md#구독-요금제) 참조.

## 인증 정보 출처

Cursor 앱 로그인 또는 `agent login`으로 저장된 인증 사용.
egasu가 세션 토큰을 얻기 위해 Cursor의 로컬 상태 데이터베이스와 키체인 항목을 읽음.
갱신 응답을 사용하기 전에 현재 선택되는 인증 출처와 액세스·갱신 토큰 쌍 재확인.
SQLite는 저장 시에도 원본 토큰 쌍을 조건부 비교해 같은 경우에만 액세스 토큰 교체.
키체인은 Cursor의 동시 변경과 안전하게 묶어 저장할 수 없어 쓰지 않고, 갱신된 토큰을 메모리에만 보관.
조회마다 인증 출처와 원본 토큰 쌍이 같은지 확인한 뒤 재사용하며, 만료 5분 전부터 다시 갱신.
로그아웃·인증 변경 또는 기본 사용량 요청에서 인증 실패가 확인되면 보관한 토큰 폐기.
갱신 중 로그인·로그아웃이나 인증 출처 변경이 감지되면 이전 응답을 사용하지 않고 새로 고침 중단; 다음 조회에서 현재 로그인 사용.
추가 설치나 설정 불필요.

## 지출 내역

Today, Yesterday, Last 30 Days, Usage Trend는 Cursor의 사용 이벤트 API에서 가져옴.
비용은 온디맨드 과금 이벤트의 `chargedCents / 100`이며, `isChargeable=false`인 이벤트의 비용은 합산하지 않음.
구독 포함·무료·실패 이벤트의 `chargedCents`는 요금제 사용 가치이므로 비용 합계에 더하지 않음.
토큰은 이벤트 종류와 관계없이 서버가 보고한 입력·캐시 쓰기·캐시 읽기·출력 토큰 합산.
구독료·세금·별도 청구 항목은 포함하지 않으며, 최종 청구서 총액을 뜻하지 않음.
신규·미등록 모델도 서버 비용과 토큰을 그대로 반영.
모델 가격표는 비용 계산에 사용하지 않고, 별칭으로 모델별 내역만 묶음.
모델명이 없는 이벤트와 토큰 없이 비용만 보고된 이벤트도 합계에 포함.
토큰과 비용이 모두 0인 이벤트는 날짜별·모델별 집계에서 제외.

현재 Mac의 날짜를 기준으로 오늘과 이전 29일 조회.
페이지마다 총건수·날짜·숫자를 검사하고, 같은 이벤트 목록이 여러 페이지에서 반복되면 조회 실패로 처리.
전체 페이지를 받은 뒤 이력 교체.
요청 실패·손상된 이벤트·페이지 누락은 부분 합계를 정상 값으로 표시하지 않고 같은 계정의 마지막 정상 이력 유지.
현재 로그인이 저장된 계정과 일치할 때만 egasu CLI에서 캐시된 사용량을 반환.
앱을 다시 열면 첫 갱신에서 서버에 사용량 요청.
같은 앱 실행 중 유효한 캐시가 있으면 현재 로컬 로그인을 다시 확인하고 같은 계정일 때만 네트워크 조회 생략.
한도 조회 실패 또는 시간 초과 시 현재 로그인과 일치하는 마지막 정상 한도와 이력 유지.
시간 초과 뒤 로그인 확인은 Keychain 승인창 없이 실행.
현재 로그인이 바뀌었거나 확인되지 않으면 오류만 표시.
누락된 기간 행에는 대시보드의 [기간 값 표시 규칙](/docs/dashboard.md#한도가-없는-지표) 적용.
완료된 빈 응답은 정상 결과이므로 이전 이력 제거.
이력 조회가 실패해도 이미 조회한 요금제·요청 사용량 유지하고 경고 표시.
429 응답은 수신 시점부터 Retry-After를 따르며, 사용할 수 있는 값이 없으면 한 시간 대기.
이 대기는 같은 Cursor 로그인에만 적용.
실패 사유는 인증 정보·응답 본문 없이 진단 로그에 기록.
서버 반영 지연으로 최신 수치가 현재 활동보다 뒤처질 수 있음.
이전 버전의 캐시에 남은 추정 비용은 새 이력 수신 전까지 추정 표시 유지.

## 서비스 상태

Cursor가 활성화돼 있으면 실행 시, 활성화 시, 5분마다, 대시보드 수동 새로 고침 시 [Cursor Status](https://status.cursor.com/)의 IDE와 cursor.com 컴포넌트 확인.
활성화 시에도 5분 성공 캐시와 서버가 지정한 Retry-After 대기를 존중하며 상태 재확인.
공개 요청은 인증 없이 실행되며 Cursor 인증 정보나 사용량 데이터를 보내지 않음.
이 제품 컴포넌트는 Cursor 사용량과 가장 가까운 공식 범위이며, 사용량 API 엔드포인트 전용 상태 감시는 아님.
두 컴포넌트 중 하나가 성능 저하, 부분 장애, 중대 장애를 보고하면 서버 해골 표시; 예약된 유지보수와 알 수 없는 결과에는 미표시.
해골을 누르면 Cursor Status를 기본 브라우저로 열기.

## 문제 해결

- **"Not logged in" / 토큰 오류** — Cursor 앱에서 로그인하거나 `agent login` 실행 후 새로 고침.
- **일부 지표 누락** — Cursor는 요금제 유형에 따라 필드를 생략하며, 누락된 지표에는 "No data" 표시.
- **선택적 조회 실패** — 기본 응답이나 다른 대체 응답에서 사용량을 얻을 수 있으면 선택적 조회 실패 후에도 새로 고침 계속.
  인증 정보를 포함하지 않은 고정 사유만 진단 로그에 기록.

## 내부 동작

통합 계정의 선불 잔액은 `api2.cursor.sh/aiserver.v1.DashboardService/GetComplatCreditBalance`, 월간 추가 사용액은 `cursor.com/api/dashboard/v2/usage-status?scope=user`에서 조회.
`api2.cursor.sh`의 Connect RPC(대시보드 사용량), Enterprise/팀 계정용 `cursor.com/api/usage`와 `cursor.com/api/usage-summary`의 두 REST 응답을 조합하는 대체 경로, `cursor.com/api/auth/stripe`의 Stripe 잔액, `cursor.com/api/dashboard/get-filtered-usage-events`의 페이지별 사용 이벤트.
대체 경로는 포함 요청 허용량과 구조화된 백분율 및 사용자 단위 온디맨드 지출을 결합하며, 어느 REST 응답도 단독으로 전체 계정 스냅샷으로 취급하지 않음.
기본 대시보드 사용량 요청은 401/403 후 토큰을 갱신해 한 번 재시도하며, 다른 대체 응답을 사용할 수 있으면 선택적 엔드포인트 실패를 치명적 오류로 처리하지 않고 진단 로그에 기록.
일별 비용은 서버가 보고한 추가 과금액 사용.
[모델 가격](/docs/pricing.md)의 Cursor 전용 요율은 이전 앱의 호환성을 위해 유지하며 현재 비용에는 미적용.
