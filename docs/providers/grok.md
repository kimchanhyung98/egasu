# Grok

Grok CLI 로그인 정보를 사용해 Grok Build 크레딧 사용량 추적.

## 추적 항목

| 지표 | 의미 |
|---|---|
| Weekly | 공유 주간 풀 사용률(Grok 통합 결제가 적용하는 한도)과 주간 초기화 카운트다운 |
| Monthly | 결제 응답에 월간으로 명시된 공유 한도의 사용률과 초기화 시각 |
| Extra Usage | USD 종량제 상한 상태(예: `$25.00 cap` 또는 `Disabled`) |
| Today / Yesterday / Last 30 Days | Grok CLI 완료 턴 원장·로그의 로컬 비용과 토큰 |
| Usage Trend | 오늘과 이전 30일의 일별 토큰 막대 차트 |

Grok이 구독 등급을 반환하면 프로바이더 이름 옆에 표시.
신규 판매 요금제는 The X Subscription의 Free·Plus·Premium·Super·Ultra와 팀·기업 계약.
SuperGrok 등을 포함한 요금제 표시 이름은 서버 응답 사용.
가격과 제공 범위는 [구독 요금제](/docs/pricing.md#구독-요금제) 참조.

공유 한도는 Grok이 현재 결제 계정에 적용하는 한도.
현재 결제 기간이 주간이면 Weekly, 월간이면 Monthly 행 표시.

## 인증 정보 출처

Grok CLI에서 한 번 로그인(`grok login`)하면 동일한 인증 파일 사용.
인증 경로는 `GROK_AUTH_PATH` → `$GROK_HOME/auth.json` → `~/.grok/auth.json` 순서.
xAI 계정의 구독 인증만 사용하며 API 키·다른 발급자의 OIDC 로그인은 구독 조회에서 제외.
메타데이터가 없는 이전 인증 파일은 알려진 `https://auth.x.ai::...` scope로 판별.
액세스 토큰은 만료 전에 자동 갱신하며, 교체된 토큰은 파일에 다시 기록.
인증 파일이 없으면 로그인 필요, 파일을 읽을 수 없으면 인증 접근 오류, 내용이 손상되면 인증 형식 오류로 표시.
토큰 갱신 요청의 로그인 거절·요청 제한·서버 오류·네트워크 실패는 [진단 로그](/docs/logging.md)에서 구분.
갱신 응답을 저장하기 전 대상 로그인 변경·삭제를 감지하면 저장과 조회를 중단하고 다음 새로 고침에서 현재 로그인 사용.
저장 전 다시 읽은 파일의 다른 로그인과 추가 필드를 보존하며, 이때 인증 파일이 없으면 다시 만들지 않음.
외부 Grok CLI가 재확인 이후 파일 교체 전까지 변경·삭제하는 경우의 보존은 보장하지 않음.
저장 전 파일을 읽지 못하면 실제 원인을 로그에 기록하고 인증 접근 오류로 조회 중단; 로그인 변경으로 단정하지 않음.
토큰 갱신은 처음 읽은 인증 파일에 저장하며 다른 홈의 파일은 변경하지 않음.

## 지출 타일

### 완료 턴 원장과 로그

Today / Yesterday / Last 30 Days는 Grok 홈의 완료 턴 원장(`sessions/<작업 경로>/<세션 ID>/usage.json`)과 로그(`logs/unified.jsonl`)에서 **로컬로** 계산.
Grok 홈은 `GROK_HOME` 또는 기본 `~/.grok`.
계보가 없는 독립 세션은 `summary.json`으로 확인한 완료 턴 원장을 우선 사용하며, 같은 세션의 로그는 합계에서 제외.
원장의 세션 누적 합계와 턴별 합계를 중복 합산하지 않음.
같은 턴의 추가 사용량·재개 후 갱신은 다음 스캔의 스냅샷으로 교체.
원장이 선택된 세션의 진행 중 턴은 다음 완료 턴 저장 때 반영.
원장이 없는 세션은 로그 사용.
원장과 함께 읽는 로그에 세션 ID가 없으면 중복 여부를 확인할 수 없어 해당 행을 제외하고 불완전 이력으로 진단.
fork·부모/자식 세션·하위 에이전트 메타데이터가 있거나 계보·모델별 합계를 확인하지 못하면 원장 기록을 합계에서 제외.
제외한 원장 기록은 수집 결과에 보존하고 진단 정보 남김.
같은 세션의 유효한 로그가 있으면 그 로그로 집계.
부모·자식 원장을 단순 합산하거나 상속 사용량을 추측해 차감하지 않음.
원장 날짜는 개별 요청 시각이 아닌 `endedAt`의 로컬 날짜 기준.
자정을 넘는 턴도 완료 날짜에 합산하며 요청별 날짜 분배는 미지원.
각 기간은 비용과 토큰을 함께 보여 주는 하나의 타일(`$4.08 · 1.2M tokens`)로, Claude/Codex/Cursor와 동일.

### 비용과 토큰 계산

완료 턴 원장의 양수 `costUsdTicks`는 제공자 보고 비용이며, `1e10`으로 나누어 USD로 변환.
보고 비용 누락·0·음수·부분 비용·불완전 사용량은 정상 토큰을 유지하고 해당 날짜·기간의 비용 합계 생략.
모델·턴·세션의 토큰 합계가 일치하고 비용 합계만 다르면 정상 토큰을 유지하며, 비용이 맞지 않는 턴 또는 세션의 비용 제외.
불완전한 완료 턴의 진단 수는 `endedAt`이 조회 시작 시각부터 현재 시각까지인 턴만 포함하며 양끝 시각 포함.
파일 읽기 실패는 턴 날짜와 별개로 실제 접근 오류로 안내.
여러 요청이 섞인 완료 턴 합계에 요청별 모델 요율을 다시 적용하지 않음.
로그의 달러 금액은 공유 [모델 가격](/docs/pricing.md)과 기록된 토큰 수로 추정.
공식 별칭 `grok-code-fast`와 `xai/grok-code-fast` 표기는 `grok-build-0.1`과 같은 모델 요율로 계산.
별칭은 구버전 가격 조회에서도 지원하며, 적용 단가·장문 요금은 해당 앱의 가격표와 해석 기능에 따름.
보고 비용과 추정 비용이 섞일 수 있어 비용 타일의 추정 안내(ⓘ) 유지.
토큰 수는 원장 또는 로그의 측정값 사용.
원장의 `inputTokens`는 cache read·write 포함이며 `totalTokens`는 input+output 사용.
별도 `reasoningTokens`를 원장 합계에 다시 더하지 않음.
모델 적용 기록의 `api_backend`가 `Responses`이면 출력 토큰에 포함된 추론 토큰은 다시 더하지 않음.
`ChatCompletions`와 `api_backend`가 기록되지 않은 로그는 출력·추론 토큰 합산.
프로세스 기본 모델(`model catalog` 기록)은 backend 기록이 없어 Responses 중복을 보정하지 못할 수 있음.
모델명만으로 API 경로를 추정하지 않음.

### 로그의 모델 식별

같은 프로세스 안에서도 세션별 모델 변경을 구분해 비용 계산.
모델 변경 요청만으로는 갱신하지 않고 실제 모델 적용 기록 사용.
프로세스 시작 기록이 나오면 해당 프로세스 ID의 이전 모델 상태를 초기화하여, ID 재사용 시 과거 실행과 분리.
세션 모델 기록이 없으면 프로세스 기본 모델 사용.
세션을 식별할 수 없는 하위 에이전트가 관측된 뒤에는 세션 확인 필요.
프로세스 기본 모델이 바뀌면 기본값을 사용하는 세션에 반영하며, 명시된 세션 모델은 유지.
세션을 식별할 수 없는 하위 에이전트 모델 기록은 다른 세션의 모델을 변경하지 않음.
하위 에이전트 관측 전 확인한 세션의 기본 모델은 유지하며, 이후 모호한 프로세스 기본값으로 덮지 않음.
모델을 연결하지 못한 세션 사용량과 하위 에이전트 관측 후 세션 ID가 없는 사용량은 합계에서 제외.
모델 연결 불가와 불완전한 완료 턴은 진단 로그에 기록하며 카드 경고는 표시하지 않음.
추정 비용은 결제 API가 반환한 크레딧 사용량과 별개.

### 기록 누락과 오류 처리

원본 로그는 이 Mac에서만 읽음.
Grok CLI는 로그가 5 MiB 이상이면 앞부분을 정리하므로 30일 전체 기록 보존은 보장하지 않음.
로그 읽기에 실패하면 부분 이력 안내 표시.
함께 읽는 다른 도구의 정상 기록은 유지하며, 전체 읽기 실패 시 마지막 정상 이력 유지.
음수·소수·표현 범위 초과 등 잘못된 토큰 수나 프로세스 ID가 있는 사용량 행은 제외하고 [진단 로그에 기록](/docs/refreshing.md#가져오기에-실패한-경우).
토큰 필드가 모두 없거나 `null`인 사용량 없음 기록은 집계와 숫자 오류 진단에서 제외.
사용량을 담지 않는 모델 변경 기록의 손상된 프로세스 ID는 숫자 오류 진단에 포함하지 않으며, 실제 사용량 행의 ID는 별도로 검증.
정상적인 과거 모델 변경은 계속 사용하여 기간 경계에 걸친 요청의 모델 식별.
누락된 기간 행에는 대시보드의 [기간 값 표시 규칙](/docs/dashboard.md#한도가-없는-지표) 적용.
표시용 0은 상단 비용·토큰 합계에 추가하지 않음.
Usage Trend는 토큰 기록이 없으면 **No data** 표시.

공유 도구 기록에 `grok` 귀속이 명시된 사용량도 같은 기간 통계에 반영.
모델 이름만으로 xAI API 사용량을 Grok 구독에 귀속하지 않음.
공유 도구와 Grok CLI 로그의 가격 미확정 기록은 토큰을 유지하고 해당 기간 전체 비용은 생략.
가격을 확인하지 못한 모델의 비용은 모델 내역에서도 생략.
The X Subscription으로 통합한 계정의 Grok Bot·Cursor 공유 한도는 통합 결제 응답으로 조회.
별도 프로바이더나 한도는 생성하지 않음.
통합 전 Cursor·SuperGrok 연결의 Bot 사용량은 Cursor 계정의 별도 grant이며 두 구독을 합산하지 않음.
Bot의 개별 요청 비용·토큰 원장은 별도 수집하지 않음.

## 문제 해결

- **"Session expired" / 인증 오류** — `grok login`을 다시 실행한 뒤 새로 고침.
- **주간 또는 월간 한도가 보이지 않음.**
  정상 결제 응답에서 확인된 기간의 한도만 표시.
  조회 실패 시 마지막 정상 한도가 있으면 해당 값 유지.
- 지출 기록이 보이지 않으면 Grok CLI의 완료 턴 원장, `logs/unified.jsonl`, 또는 `grok`으로 귀속된 공유 도구의 기록을 확인.
  토큰 수를 남기지 않는 CLI 버전의 기록은 집계 불가.
  Grok CLI 또는 지원 공유 도구에서 Grok을 사용한 뒤 새로 고침.

## 내부 동작

현재 기간의 공유 한도와 종량제 상한은 `GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`로 조회.
요금제 이름은 같은 서버의 `/v1/settings`로 조회.
요금제 조회만 실패하면 확인한 사용량을 유지하며 HTTP·응답 형식 오류를 로컬 로그로 기록.
토큰 갱신은 `auth.x.ai` 사용.
401/403 응답 시 토큰을 한 번 갱신하고 재시도.

## 공유 도구 사용량

공통 수집 대상은 Pi·Oh My Pi(OMP).
도구별 경로·중복 제거·가격 규칙은 [사용량 수집](/docs/usage-collection.md) 참조.
계정 귀속을 확인하지 못하는 기록은 계정 전용 카드에 합산하지 않음.
공통 수집이 실행되면 읽지 못한 저장소를 경고하고 읽은 기록은 보존.
Grok CLI 이력의 실패 처리와 화면 반영은 위 기록 누락·오류 처리 규칙 적용.
Grok CLI 로그를 읽지 못하면 공유 기록만 표시될 수 있으며, 카드 경고에 불완전 이력 안내.
기록에 명시된 프로바이더 귀속과 공통 가격 엔진 사용.
모델 제조사만으로 구독을 추측하지 않음.
공유 도구의 가격 미확정 토큰은 유지하고 해당 기간의 총비용 생략.
